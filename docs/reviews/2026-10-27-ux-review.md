# GlossMark: UX review of the human surfaces

Reviewed on 2026-10-27 against GlossMark `main` at ebfa5f2 (v0.3.0). I built `gloss` from the tree and used it on three projects: a new four-file repository (to test the first run), `examples/library` (CLI, review TUI, PR comment) and the `clinic-booking` showcase in glossmark-examples (viewer). The viewer was rendered in headless Chromium at 1440 px light, 1440 px dark and 390 px. The review TUI was run in a 120×35 pseudo-terminal.

This review does not repeat [the 2026-10-18 adoption review](2026-10-18-adoption-review.md), which covered ontology modelling and agent experience. It looks at what a person sees and does, and asks one question of each surface: does it tell the user what happened, why it matters and what to do next?

## Summary

The engine is ahead of its interface. Diagnostics name the file, line and rule. The gate model (AUTO/SOFT/HARD) is a clear mental model, and `doctor` gives a fix on every line. The friction comes from three patterns that recur on every surface:

1. **Output describes and stops.** `drift`, `check`, `coverage`, the PR comment and the viewer report state well but rarely name the next command. An empty repository after `init` reports zeros and does not point to `suggest`.
2. **Everything is shown at once.** The help lists 29 commands alphabetically, the viewer legend has 26 entries, and the review queue opens with 16 HARD findings and 4 proposals in one list. Nothing separates the starter path from the expert one.
3. **The UI talks in internal vocabulary.** `overlap`, `presented-only`, `housed`, `surface`, `lifted`, `rollup ⊄ declared`, `finding:orphan:lib:HoldReady`: each term is defined somewhere, but surfaces use them without explanation.

Fixing those three patterns would do more than any single feature. The findings below are grouped by surface and ranked by severity: **High** (misleads the user or blocks them), **Med** (costs time on every use) and **Low** (polish).

## 1. First run and onboarding

| # | Sev | Finding | Recommendation |
|---|---|---|---|
| 1.1 | High | `gloss doctor` reports a false warning right after `gloss init`: `! agent hook: SessionStart hook registered but no MCP server in .mcp.json → gloss hook install`. The file exists. When `gloss` is not on `PATH`, `hook install` writes the absolute binary path into `.mcp.json`, and `internal/doctor/doctor.go:227` looks for the literal `"gloss"`. The suggested fix rewrites the same file, so the user is stuck in a loop. | Parse `.mcp.json` and check for a `glossmark` server whose `args` contain `mcp`, not for a substring. Add a test that uses an absolute command path. |
| 1.2 | High | The same fallback writes a machine-specific path (here `/tmp/claude-0/gloss`) into `.mcp.json` and `.claude/settings.json`, and `init` tells you to commit both. A teammate who clones the repo gets a hook that fails silently (`|| true`). | Write `gloss` by name to committed files. Put the absolute path in `.claude/settings.local.json` (git-ignored), or say once that `gloss` must be on `PATH`. `doctor` should flag absolute paths in committed agent config. |
| 1.3 | High | After `init`, the repository is a dead end. `check`, `drift` and `coverage` all report zeros or `n/a` without a next step, and the init epilogue ("name the core concepts…, mark the code (docs/MARKING.md)…") never mentions `harvest`, `suggest --concepts` or the `adopt-glossmark` skill, which do most of that work. | End `init` with a numbered three-step path that matches the tooling: `gloss suggest --concepts` (or the skill), review, `gloss suggest`. Make the empty states actionable: "0 concepts defined. Draft some with `gloss suggest --concepts`." |
| 1.4 | Med | The "no glossmark.yaml found" error does not say how to create one. | Append "run `gloss init` to set up this repository". |
| 1.5 | Med | `init` derives prefixes from the repository name's initials (`newrepo` gives `ne:`, `nei:`, `neb:`). These IRIs end up in every marker, so they are expensive to change later, and the user is never asked. | Show the prefixes before writing and take `--namespace` and `--boundary-prefix` (F-ADOPT-1 asks for the latter). On a terminal, prompt with the guess as the default. |
| 1.6 | Low | The `init` plan promises `.glossmark/ledger.jsonl`, `doctor` then says the ledger "does not exist yet", and `doctor` marks `GLOSS_ACTOR: unset` with ✓ while the same line says agents need it. | Have `init` create an empty ledger, or drop it from the plan. Mark the unset actor `·` (info) rather than ✓. |

## 2. CLI

| # | Sev | Finding | Recommendation |
|---|---|---|---|
| 2.1 | Med | `gloss` with no arguments lists 29 commands alphabetically, each with a dense one-line description (the `mcp` line names 17 tools). A newcomer cannot tell that `check`, `drift`, `review` and `view` are the core loop and `landscape`, `publish`, `lock` and `export` are rarely used. | Group the help: **Start** (init, doctor), **Daily** (check, build, drift, review, view), **Pull requests** (diff, impact, accept, reject, status), **Agents** (hook, context, mcp, agents), **Ontology** (propose, suggest, harvest, import, criticality), **Advanced** (the rest). Keep each description under 70 characters and put the detail in `-h`. |
| 2.2 | Med | `gloss <cmd> -h` prints Go's default `Usage of gloss check:` plus flags: no description, no examples and no link to the docs. | Give each subcommand a usage line, two or three examples and a docs link. `check -h`, `drift -h` and `review -h` matter most. |
| 2.3 | Med | An unknown command prints the full 29-line help after the error, which pushes the error off a short terminal. Typos in markers get no suggestion: `implemnts` lists all 17 relations, and `lib:Retrun` says only "does not exist". | Print "unknown command 'chek'; did you mean 'check'?" and nothing else. Add edit-distance suggestions to GM200 and GM215 ("did you mean lib:Return?"). Agents benefit from this as much as people. |
| 2.4 | Med | `drift` ends with `3 failing findings (violation,value-drift,gap,dangling,overdue,planned-closed,plan-overdue)`. The parenthesis lists the configured `--fail-on` kinds, not the three that failed, so it reads as seven failures. | `gloss drift: failed: 2 violations, 1 gap (fail-on: violation, gap, …)`. |
| 2.5 | Med | `drift` sections have no next action. The same finding vocabulary is repeated on each line ("orphan concept" under the heading "Orphan concepts"). | Add one hint per section heading (Violations: "widen the manifest or move the code; `gloss review` to waive"). Drop the repeated noun from each line. |
| 2.6 | Low | The same metric is printed differently: `22%` in `drift`, `22.2%` in `coverage`. `review backlog oldest 0 days` appears on an empty repository. | Use one format for percentages. Omit backlog age when the backlog is empty. |
| 2.7 | Low | Output is plain text on a TTY; ✗, ○ and ? carry the severity alone. | Add colour on TTY that honours `NO_COLOR`: red violations, amber gaps, dim orphans. Keep the glyphs for colour-blind users and logs. |

## 3. Viewer (`gloss view`)

The viewer has come a long way: boxes for boundaries, a drift panel, filters with counts, slicing and dark mode that works. What remains is mostly about legibility and access.

| # | Sev | Finding | Recommendation |
|---|---|---|---|
| 3.1 | High | The graph is a `<canvas>` with no accessible alternative. No node can get keyboard focus, no element has an `aria-label`, and tabbing goes from the toolbar into the drift summaries and then to `<body>`. A keyboard or screen-reader user cannot select a concept, so the concept pane (artifacts, tests, doc) is unreachable for them. | Add a list or tree of the current view's nodes as a keyboard-navigable alternative (it could replace the "Where you are" list), with arrow-key navigation and Enter to select. Add `aria-live` on the details pane. Label every toolbar control. |
| 3.2 | High | The hover tooltip gets stuck. After a node is clicked, its tooltip stays on screen through a view switch, a search and opening Filters, and covers a quarter of the canvas (seen in all four follow-up screenshots). | Hide the tooltip on `mouseleave`, on selection, on view change and on any toolbar action. |
| 3.3 | Med | Encoding overload. The legend has 26 entries in 7 visual channels: fill colour, ring colour, ring count, dash pattern on node outlines, dash pattern on boxes, dash pattern on edges, and numbered badges. Two of these are not in the legend at all: what node fill colour means, and what the badge numbers (1, 2, 3, 5, 6) count. | Explain fill and badges, or remove them. Show only the legend entries present in the current view, and collapse the legend by default ("What these mean" already exists). Give each view a primary encoding: criticality in business, drift in engineering. |
| 3.4 | Med | Search dims non-matches but gives no count and no way to step through results. Matches inside closed boundaries are invisible: `cancel` highlights `clinic:Cancellation` while `CancellationWindow` and the Cancellation boundary contents stay hidden. Enter does nothing. | Show "3 matches · 2 inside closed boxes", ring a closed box that contains a match, and make Enter / Shift+Enter step through matches, opening boxes as needed. Add `/` as a shortcut to focus search. |
| 3.5 | Med | The concept pane contradicts itself: two `in boundary` rows say "Larkspur clinic booking" and "none: no boundary's code realizes it". The name is shown twice when the label equals the id. Artifact paths wrap mid-segment (`booking-↵api`) and are not links. | Merge them into one row ("housed in Larkspur clinic booking; no boundary realizes it directly"). Hide the label line when it equals the id. Make paths links: `vscode://file/…` or a `--source-url` template for GitHub. Use `overflow-wrap: anywhere` only on path separators. |
| 3.6 | Med | The business view shows `clinic:` on every node. For a practice manager the prefix is noise, and in the engineering view it makes boundary labels truncate (`Patient s…`, `AWS infrastru…`, `Booking …`). | In views whose namespace is uniform, show the label without the prefix and put the prefix in the header ("namespace clinic"). Fit box labels before truncating, and show the full name on hover. |
| 3.7 | Med | The engineering view at container zoom is a hairball: 18 nodes and 55 edges, most of them dashed derived edges crossing the whole box. | Draw derived and lifted edges only for the selected or hovered node, and bundle parallel edges into one edge with a count. |
| 3.8 | Med | At 390 px, the toolbar overflows (page `scrollWidth` 409), "Theme: auto" is cut off, and the graph renders at zoom 0.43, so labels are unreadable. The details sheet is good. | Wrap the toolbar or move secondary buttons (Expand all, Collapse all, Re-layout) into a menu. Open on mobile at a readable zoom, centred on the top box. |
| 3.9 | Low | Opening Filters pushes the whole canvas down by 270 px. Chips show no on/off state, and nothing indicates that a filter is active once the panel is closed. | Render Filters as an overlay or side sheet, give chips a pressed state, and show "2 filters active · reset" on the toolbar. |
| 3.10 | Low | The `unplaced · surface` label overlaps the dashed border of its own box. The `system · 6 more inside` header appears on a box that is already open. Edge labels (`revers…`, `produces`) are cut off by nodes. | Collision-check box labels, say "6 folded" or omit the count on open boxes, and place edge labels at the midpoint with a background halo. |
| 3.11 | Low | `overlap 12` is the largest drift group and the only kind not explained in `drift` output. | Explain each kind in one line inside its `<details>`, and link "What these mean". |

## 5. Pull request comment (`gloss diff --format markdown`)

Issue #191 already tracks a redesign. Two observations to feed into it:

- **Contradictory verdict (High).** The comment's headline is `gate AUTO … No ontology-relevant changes … nothing to review`, while the same block lists two rollup violations marked ✗. A reviewer reads "nothing to do" and skips the violations. When drift findings exist, say so in the headline even if this diff did not introduce them ("AUTO for this change · 2 existing violations on the base").
- **A code block is the wrong container (Med).** A wide `text` block scrolls horizontally on GitHub and in mobile notifications. Use a short table (gate, views changed, concepts changed, coverage delta), then a `<details>` section per boundary.

## 6. Cross-cutting: language

The product's terms are precise but dense. Two low-cost changes:

- **A glossary of GlossMark's own terms** (finding kinds, placement, gates, tiers), linked from `drift`, the viewer's "What these mean", `review ?` and the PR comment. Every surface should link to the same definitions.
- **Write user-facing strings as consequence and action, not mechanism.** Compare `rollup: produces {lib:Item} (from lib:Book, lib:DVD, lib:Laptop) ⊄ declared` with "circulation-svc now produces lib:Laptop, which its manifest does not allow. Add it to `produces:` or move the code." Keep the precise form behind `--explain`.

## Appendix: reproduction

- First run: `mkdir r && cd r && git init && mkdir src && echo 'def f(): ...' > src/a.py`, then `gloss init` (with `gloss` not on `PATH`), `gloss doctor`, `cat .mcp.json`.
- Viewer: `gloss view` in `glossmark-examples/showcase/clinic-booking`. Click `clinic:Booking`, switch to `engineering`, type `cancel` and press Enter, open Filters. The tooltip stays through each step.
- TUI: `gloss review` in `examples/library/circulation` at 120 columns.
- PR comment: `gloss diff --base HEAD~5 --format markdown` in `examples/library/circulation`.
- Typos: add `# @gloss implemnts lib:Renewl` or `# @gloss implements lib:Retrun` to `services/circulation/loans/renew.py` and run `gloss check`.
